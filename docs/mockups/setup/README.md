# Setup page: build target (operator-approved 26 Oct 2026)

`setup.dc.html` is the approved v3 mockup (design-canvas source; read it, it only renders in the canvas). Setup is configuration, laid out top to bottom in dependency order; no live status.

1. **Accounts** first: Codex accounts each have their own login profile (`cli_profile`, absolute, already signed in), so several can coexist; Claude today uses the machine's one login (the hub refuses a profile for non-Codex accounts), so one Claude account until per-account Claude profiles are built. the models found and when they were last checked (Refresh), 5h/7d usage bars inside their columns with a burn projection, resets, alert/stop thresholds. Add, Edit, Sign in again, Remove (refused while in use, naming where).
2. **Repos & seats**: one card per repo, Crew or Observed, default account, checkout. Work guidance is advice for FLIGHT, not rules: priority, milestone, labels (any of / all of) and avoid, all multi-select; a free-text direction. Seats live inside their repo, config only: role (plain-English label + call sign), account (repo default or override), model and effort picked from that account's discovered list, enabled. Add repo: repo → checkout folder → live checks → mode and account. Observed repos show their external loop read-only with Convert to crew.
3. **Roles**: plain-English label + call sign, one-line purpose, Good at, and the prompt as standard sections (shared Mission Control context, the role, repo rules first, handoffs, comms, done/escalate). No accounts, models, areas or review depth here (#712 rewrites the prompts).
4. **Loops**: build `docs/mockups/loops/loop-chain.html`. **Ignore the Loops tab inside `setup.dc.html`**: it is an earlier, superseded design.
5. **Safety**: the three hard stops (secrets and home, git and GitHub via PRs, observed repos read-only), the network policy, and the refusals log with Allow from now on for non-floors. Final shape pending the operator.
