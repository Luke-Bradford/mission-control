### Server contract supplied by the dependency

Use core's `StandingInstruction` union and list/mutation types; do not duplicate schemas in the UI.
Rows have ID, target (global FLIGHT or named seat), kind (text/focus), text/focus value,
by (operator/flight), at, revokedAt and source (saved/legacy-config).
Global orders apply across the hub; do not add a repo scope selector.
Seat focus null is an explicit clear, not a missing instruction.

- `GET /api/flight/orders?before=<id>&limit=50` returns complete active rows plus revoked history and nextCursor.
- `GET /api/flight/orders/:id` returns one retained global order, active or revoked, for stable decision links.
- `POST /api/flight/orders` takes `{text,replacesId?}`; returns the saved row.
- `POST /api/flight/orders/:id/revoke` takes `{}`; returns the retained row.
- `GET /api/seats/:id/instructions` returns the lists plus effectiveFocus and focusInstructionId.
- `GET /api/flight/instructions` returns a page-shaped active seat index with effective focus.
- `POST /api/seats/:id/instructions` takes `{kind:"text",text,replacesId?}` or
  `{kind:"focus",focus:string|null,replacesId?}`.
- `POST /api/seats/:id/instructions/:instructionId/revoke` takes `{}`.
- Existing GET/POST `/api/seats/:id/focus` keeps the `{focus}` compatibility shape and adds source metadata.

History defaults to 50 rows, maximum 100; paginate only history. Never silently cap the active set.
Text permits 4,000 UTF-16 code units; focus retains the 500-character selector validator.
The service rejects more than 64 active rows or 64 KiB of active rendered content per target.
Show the actual server conflict/capacity error and retain the draft.
Malformed input returns 400, protected writes 403, unknown targets 404 and conflicts/capacity 409.
Never send author, timestamps or operator-token data as editable fields.

Add resource/action entries in `apps/web/src/data.ts` with appropriate flight/config/agents topic invalidation.
Use existing authenticated API helpers. Refresh the affected active/history/decision/focus readers after success.
Do not introduce a second data cache or poll hidden tabs.

### Add, edit, revoke and failures

Provide named Add order and Add seat instruction actions. Editing appends a replacement using replacesId;
it does not overwrite historical text. Revocation is an explicit action and retains the old row.
Do not optimistically remove entries before the API succeeds.
Keep entered text and selected target through validation errors, server failure and disconnection.
Disable duplicate submission while pending; focus a named error summary and restore focus after closing.
Use labels above fields, useful widths and grouped Save/Cancel controls from the shared form contract.

Explain precedence in short local help: global operator orders outrank memory and seat instructions;
operator seat instructions outrank FLIGHT's. All remain subject to repo rules and safety floors.
Show FLIGHT-authored rows plainly; operator actions may replace/revoke them through normal authenticated routes.
Imported focus rows say "Imported from config" and show import time, not an invented original human author/date.

### Focus and decisions

Keep the existing Queue focus editor and selector help. Do not rebuild it as a second form.
Show its effective value and source ID. Clear creates an active operator null instruction,
so the queue becomes unrestricted without revealing a hidden FLIGHT filter.
An active operator focus outranks FLIGHT, including an explicit null clear.
Revoking that operator focus may reveal an active FLIGHT focus; show the resulting value/source
in the revoke action's context before submission. Distinguish revoke from Clear.
Surface server conflicts honestly; this UI must not reinterpret selectors or change queue eligibility.

The dependency adds `re-plan` and `instruction` decision kinds and optional `orderId` to FlightDecision.
Add readable labels in `flight/conversation.ts`; keep existing Did-tab filters working.
Re-plan rows link to the exact numbered order in Knows, opening its history section when revoked.
Resolve deep links through the retained-order detail endpoint; keep pagination for browsing history.
Do not show a revoked order as active.
Reuse existing tab/hash conventions and decision anchors, with keyboard-accessible links and full text.
An unknown/deleted reference remains an explicit unavailable state; never invent order content or an effect.
