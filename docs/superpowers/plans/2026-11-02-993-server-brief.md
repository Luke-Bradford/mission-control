# Draft child: FLIGHT keeps operator orders and seat instructions across wakes, with linked re-plan decisions

Parent: #993, including closed #763. Proposed labels: `area:server`, `type:feature`, `lane:home`.
Size L. Draft only; no crew start is authorised. Source baseline: `f7ee4e26`.

## Outcome

The hub saves global operator orders and named-seat instructions with IDs, authors, dates and revocation history.
Every FLIGHT wake carries active orders after verified direction and before memory.
FLIGHT can save seat instructions and logs each change. It cannot change operator entries.
An affected planning decision names its saved order through a typed `re-plan` reference.

## Why

#993's 31 October comment folds #763 into one store with two targets: FLIGHT and named seats.
Both features remain unavailable placeholders in `apps/web/src/flight/KnowsTab.tsx:5–23`.
Repo memory is mutable, selectively injected context, not an order store.
Queue focus already works; preserve its UI, persistence and selector behavior.

### Store and shared types

Add a shared `StandingInstruction` union and input/read/mutation types in core, exported through its index.
Use one table in `apps/server/src/store.ts`:
`id INTEGER PRIMARY KEY AUTOINCREMENT, seat_id TEXT NULL, kind TEXT, text TEXT NULL,
by TEXT, at INTEGER, revoked_at INTEGER NULL, source TEXT DEFAULT 'saved'`.
`seat_id=NULL` means a global FLIGHT order, always operator-authored plain text.
Seat rows are plain text or focus. Focus null means an explicit clear.
`by` is operator or flight; `source` is saved or legacy-config.
The service derives authority, ID and dates from authenticated context; client fields cannot spoof them.

Rows are immutable except revocation. Retain revoked rows beyond ordinary memory/decision pruning.
Edits create a replacement and revoke the original transactionally, using optional `replacesId`.
Revoke twice returns the original timestamp without another audit/notice.
Order rows stay global; use existing configured-seat/session authority for seat writes.
Add no new cross-repo permission restriction contrary to #1214.

Proposed new bounds: plain text at most 4,000 UTF-16 code units; each target at most 64 active
entries and 64 KiB of rendered active content. These are implementation proposals, not existing order limits.
The text bound follows memory/decision constants in core flight.ts:199,366; the aggregate bounds are new.
Plain text is trimmed and nonempty. Focus keeps existing seatFocus validation, including its 500-character bound.
Check capacity transactionally before saving. Reject oversize changes with an actionable error;
never trim, omit, evict or lose an accepted entry. Return complete active lists.
Paginate revoked history newest first, 50 default, 100 maximum, with an ID cursor.

### APIs and authority

Implement these proposed routes in `apps/server/src/api.ts`:

- `GET /api/flight/orders?before=<id>&limit=50`: `{active,history,nextCursor}`.
- `GET /api/flight/orders/:id`: one retained global order, active or revoked, for stable decision links.
- `POST /api/flight/orders`: `{text,replacesId?}`; returns saved row.
- `POST /api/flight/orders/:id/revoke`: `{}`; returns retained row.
- `GET /api/seats/:id/instructions`: same lists plus `{effectiveFocus,focusInstructionId}`.
- `GET /api/flight/instructions`: active instructions grouped by configured seat, including effective focus.
- `POST /api/seats/:id/instructions`: `{kind:"text",text,replacesId?}` or `{kind:"focus",focus:string|null,replacesId?}`.
- `POST /api/seats/:id/instructions/:instructionId/revoke`: `{}`; stored target must match.

Use existing operator-token authentication and common declared-actor validation.
Require a configured matching operator token for instruction HTTP mutations, even in app fixtures; otherwise return 401.
Global order writes accept operator provenance only; FLIGHT never has an order-writing tool.
Seat route writes with declared FLIGHT provenance are FLIGHT entries and cannot replace/revoke operator entries.
An operator can revoke either author's seat entry. Reject a seat bearer as operator authority.
Keep global writes outside `mc operator`'s permitted POST routes.

After common header validation, protect actions using presence of `x-mc-flight-actor`.
Do not reclassify with `flightActor(req)` after parsing or awaiting work: the actor run can end meanwhile.
Follow the fix at `api.ts:5688`. Test run completion during body parsing, malformed/stale actors,
encoded routes, seat tokens and tokenless writes. Refusals must leave rows, focus, audit and notices unchanged.
Return 400 for invalid input, 403 for protected writes, 404 for unknown/mismatched targets, 409 for conflicts/capacity.

### FLIGHT tools and change notices

Add only `instruct_seat` and `revoke_instruction` as new write tools in `flight/tools.ts` and core's MCP catalogue.
Use existing `flightCall`, configured-seat resolution and basis requirements.
Inputs: instruct `{seat,kind,text?|focus?,replacesId?,basis}`; revoke `{id,basis}`.
Target/author checks happen inside the mutation service, including compatibility routes.
Each successful FLIGHT mutation records one visible `instruction` decision with ID, seat, action and basis.
Reuse existing audit/runaway accounting once per mutation; refusals and idempotent retries add nothing.

Persist a change notice through `sendComms` and the `supervisor.message` path used by message_seat.
Notify a live seat without interrupting, stopping or un-parking it. Busy seats receive an inbox notice.
Report saved/delivery status accurately. A failed delivery leaves the saved instruction and durable notice intact.
Keep the Comms notice short, within its existing limit. At provider delivery, include the complete current
seat-instruction snapshot and explicit replacement/revocation state, superseding older prompt snapshots.
Do not truncate full instruction content into the Comms message limit.
Do not require or start a real provider to test any of this.

### Focus compatibility

Preserve `focus.ts` selector grammar and `matchesFocus` semantics at all queue eligibility/start checks.
Keep the existing GET/POST `/api/seats/:id/focus` and Queue focus UI contract.
Route legacy POST focus and `message_seat {focus}` through the same instruction service.
GET focus and `message_seat {read_focus:true}` return the resolved value; source metadata is additive.

Import an explicitly configured focus, including null, once as an operator-controlled legacy-config row.
Use import time, not an invented original date. Preserve source for truthful UI attribution.
Track the last observed raw config field through existing settings. Explicit later config changes create
operator-controlled replacements; deleting a previously present field records a clear.
An omitted field preserved by config-write is unchanged. Never reimport a projected runtime focus as raw config.

The effective focus is newest active operator row, otherwise newest active FLIGHT row, otherwise null.
Replacing focus revokes the previous focus row of that same authority, retaining history.
Operator null is an active clear and outranks FLIGHT. Operator Clear therefore preserves today's unrestricted result.
FLIGHT Clear cannot clear an operator filter. FLIGHT focus writes while operator focus is active return a conflict.
Revoking operator focus can expose active FLIGHT focus; return that effective value and source explicitly.
Use this resolver for all readers and queue rechecks; do not keep a separate unprotected config write path.

### Prompt delivery and wake revisions

Add a shared final-delivery envelope for initial, repeated, rotated, resumed and operator-message FLIGHT wakes.
Resolve current active orders inside queued delivery, so a revoke during queueing is respected.
The order is hub/safety guidance, verified direction, all active global orders, applicable seat instructions,
then existing wake/context/memory. Preserve original message origin/content, inbox acknowledgement and replay keys.
Global orders outrank memory and seat instructions; operator seat entries outrank FLIGHT entries.
List entries in saved-time/ID order with author/date. Preserve conflicts; FLIGHT uses the existing brief
flow when the operator's intended precedence cannot be resolved from the saved instructions.
Neither can loosen repository rules, hard-rule approvals, budgets or safety floors.

Read docs/direction.md from verified Git objects at the watch checkout's selected base alongside repo-doc loading.
Persist run-scoped `{sha,text}` for restart/resume. Mark a missing file explicitly.
The proposed new direction-content bound is 64 KiB, following the existing repo-doc budget in brief.ts:37.
Refuse unsafe/non-regular/invalid or above-bound direction content with an explicit recovery error;
never truncate it silently. Rotation loads its selected new base. Resume uses retained context;
if missing, rebuild from a verified base and label that source. Do not trust agent-editable worktree files.

Append seat instructions after repo CLAUDE.md and AGENTS.md on start/resume in `runtime/brief.ts`.
Live changes use the durable notice, not an assumed system-prompt rewrite.
Add instruction revision/IDs to wakeFacts and pending delivery tracking, and emit relevant bus topics.
New/revoked orders wake FLIGHT without unrelated ticket changes. Advance delivery revision only after send succeeds.
Unchanged orders remain in every envelope without causing a permanent wake loop.
Update prompt-cost section accounting to include direction/orders honestly.
