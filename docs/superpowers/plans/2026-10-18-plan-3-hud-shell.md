> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the Plan 2a/2b pages with the Mission Control HUD — global chrome, FLIGHT dock, Overview, FLIGHT, Board, Agent, Comms, Telemetry, Setup, Away modal, Item panel, keyboard shortcuts — showing only what today's store, transcripts, GitHub and this Mac can tell us.

**Architecture:** The server gains read paths and two small writes: a per-run **transcript digest** folded alongside the existing token fold (tools, turns, live tool, context and its window, subagents, per-minute tokens) and kept in its own table, an on-demand **agent stream** read backwards from the current transcript, a **machine sampler** job, PRs linked to tickets **by branch name**, a slower **flow history** reader (issue Status changes and first-push CI), server-built **attention items** with acknowledgements, and persisted **away settings**. Pure rules (HUD state, board column, attention kind) live in `@mc/core`. The web app is rebuilt as the HUD: the mockup's CSS is ported as plain CSS, each page is a React component reading API resources through the existing data hub, and anything the engine or FLIGHT will provide later renders as an honest placeholder, never as sample data.

**Tech Stack:** as Plans 2a/2b — Fastify 5, React 19, SQLite via `node:sqlite`, Vitest + Testing Library + jsdom, Biome, Vite 7; one new dependency, `@fontsource/barlow-semi-condensed` (5.3.0, weights 500/600). Charts are hand-written SVG (no chart library).

## Review Focus

1. **Transcript content that is huge, malformed or hostile** — a 10 MB transcript mostly `stream_event` lines, a truncated last line, a non-JSON line, one line bigger than the scan cap, text containing `<script>`/`<img onerror>`, ANSI escapes, a `ghp_…` token, a JWT or a PEM private key: the stream reads backwards in chunks up to `STREAM_SCAN_BYTES` until it has `limit` events, skips bad and oversized lines, cleans every text, and the page shows it as inert text. → Task 2 tests, Task 12 test.
2. **A source that is missing** — a loop with no runs, a run whose transcript is gone, a running run with no `result` line yet (no context window), a deleted worktree, a repo with no `origin/HEAD`, a GitHub project without `Size`, a PR with no checks, the first machine sample: each shows an empty or `—` state with its reason; no 500, no blank page. → Tasks 2, 3, 4, 5, 12 tests.
3. **A long tool call is not a stall** — a full test suite inside Bash prints nothing to the model for 15 minutes, but the CLI writes `tool_progress` heartbeats every 30 s: "last output" is the later of the newest event timestamp and the transcript file's mtime, so heartbeats keep the agent Running; only a file that stops growing for `STALL_MS` makes it Stalled. (**Decision:** a run that has printed its `result` and then waits silently on a background shell for 10 minutes does count as Stalled — nothing is being written.) → Task 1, Task 2 and Task 4 tests.
4. **"Today" in the operator's timezone** — the MET clock's first run today, KPIs "today" and "Where agent time goes" use `config.operator.timezone` day boundaries via one helper, `startOfLocalDay` (Task 1): a run spanning midnight is clipped to today, and on 2026-10-25 (a 25-hour day in Europe/London) a run across the repeated 01:00 hour is counted once by wall time, and at 23:00 local the elapsed denominator is 24 h, not 23. → Task 1, Task 4 and Task 7 tests.
5. **Acknowledgements and flapping sources** — a stall that ends and starts again on a new run must pulse again (stall keys include the run id); a collector that recovers and fails again must pulse again (error keys include its last success time); a GitHub search that misses an acked escalation for one poll must not re-pulse it when it comes back (acks for absent keys are kept 7 days, then pruned by the scheduler). → Task 4 tests.

Real shapes (checked 2026-10-18 across recent studio fire logs and TA iteration logs):
- `assistant` / `user` lines carry an ISO `timestamp` and `parent_tool_use_id` (non-null = a subagent's frame). An assistant **repeats once per content block with the same `message.id` and identical `usage`**: de-duplicate by `message.id` (as the token fold does) for every usage-derived number.
- `assistant.message.content[]`: `text`, `thinking` (text usually empty), `tool_use {id, name, input}`. `user.message.content[]`: `tool_result {tool_use_id, content, is_error}` or `text` (top-level user text is rare: the loops' prompt is not echoed).
- `result` lines: `total_cost_usd`, `modelUsage: { [model]: { contextWindow, … } }` (1 000 000 for every model on 2026-10-18). A running run has no `result` yet.
- `system` subtypes: `init {model}`; `task_started {task_id, task_type, subagent_type?, description}` — only `task_type: "local_agent"` is a subagent (`local_bash` is a background shell, ~90 % of starts); `task_progress {task_id, usage:{total_tokens, tool_uses, duration_ms}}`; `task_updated {task_id, patch:{status, end_time}}` with `status` in completed / failed / killed / null; `task_notification {task_id, status, usage?}`; `vcs_state_changed {kind, branch?}` (branch usually absent); `code_change_published {action, url, branch?}`.
- `tool_progress {tool_use_id: "<id>-heartbeat-N", parent_tool_use_id: <the tool's id>, heartbeat: true}` every 30 s, no timestamp — never a subagent frame; only the file mtime reflects it.
- `task_notification {task_id, status, usage: {total_tokens, tool_uses, duration_ms}}` carries a subagent's **final** numbers (the last `task_progress` can be far lower).
- Parse as an **allowlist**: `assistant`, `user`, `result`, `rate_limit_event` (the existing fold reads it for the Claude quota fallback — keep that), and the `system` subtypes and `tool_progress` named above; every other line type (`stream_event` — most of a TA transcript's bytes —, `thinking_tokens`, `status`, `hook_*`, `informational`, `permission_denied`, `background_tasks_changed`, `api_retry`, …) is skipped. `stream_event` lines are skipped by their `{"type":"stream_event"` prefix before `JSON.parse`.
