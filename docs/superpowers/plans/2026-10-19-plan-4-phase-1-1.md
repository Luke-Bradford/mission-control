> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Fix what the phase 1 review found broken or misleading in the live HUD, build the unplanned mockup gaps that today's data can already serve, and let the operator see how repos differ and add one from the HUD.

**Architecture:** Same shape as Plan 3. Pure rules go in `@mc/core`; the server gains a few stored facts (a run's PRs and one-line summary, an issue's open/closed state, a loop driver's stop, agent state changes), a budgeted one-time **backfill** of older runs, and the first server write to its own `config.yaml` (add a repo, validated, backed up, applied without a restart). The web app changes are fixes inside existing pages plus a Repos section in Setup and a Together / Apart board layout.

**Tech Stack:** As Plan 3 — Fastify 5, React 19, SQLite via `node:sqlite`, zod 4, `yaml` 2 (its `parseDocument` keeps comments), Vitest + Testing Library + jsdom, Biome, Vite 7. No new dependencies.

**Spec:** issue #26 (the review findings and the operator's decisions of 2026-10-19), read with `docs/superpowers/specs/2026-10-18-mission-control-design.md` and the catalogue `docs/prototype/mission-control-hud-catalogue.md` ("cat §x"). ## Review Focus

1. **`config.yaml` that is not what the server loaded** — hand-edited since start (with comments, another repo added), invalid YAML, a repo id or `github`+`project` already present, the disk full or the directory read-only mid-write, two Add clicks at once: the server re-reads the file, keeps its comments, refuses a duplicate with 409, writes nothing when the current file does not load, never leaves a half-written file, keeps the backup, and serialises writers. → Task 15 tests.
2. **The backfill against a real archive** — 2,400 runs and 5 GB of transcripts, files up to 21 MB, some missing, some truncated mid-line: it never runs more than its budget per tick, never blocks the live collectors' ticks, resumes after a restart where it stopped, marks a missing or unreadable transcript done instead of retrying it forever, and never opens a loop file for writing. → Task 5 tests.
3. **GitHub saying two things** — an issue closed on GitHub whose Project Status still says In progress, an open issue whose Status is Done, an issue with no Status, one with both a Priority field value and a `p1` label, a repo whose project has no Priority field: closed goes to Done with a "Status out of date" flag, open-in-Done keeps Done with the same flag, no Status lands in Backlog, the field wins over the label, and nothing counts a closed issue as in progress. → Task 3 tests.
4. **Driver stops that are not quota stops** — an operator-signal STOP (stays Blocked through the escalation, not Stopped), `MAX_FIRES` reached, "stalled 3 fires with no progress", a quota STOP with no `quota window:` line, a reset time already past, a new FIRE after a stop: each shows the right state and the full reason, and a new fire clears the stop. → Task 7 tests.
5. **Session, lane and ticket route together** — session `s/shop-app` with the stored lane `site-builder`, a deep link `/board/site-builder/12` while session is shop-app, a repo added while the Board is open: the session wins (only its repo's cards, with a note when the lane or link names another repo), opening a ticket never changes the lane, and the new repo appears without a reload. → Tasks 2, 17 tests.
